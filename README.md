# 포켓몬 피규어 아카이브 v5 Online Beta

기존 v4.1의 로컬 기능을 유지하면서 Supabase 계정·클라우드 동기화·친구 도감 비교를 추가한 버전입니다.

## 추가 기능

- 이메일 회원가입과 로그인
- 사용자 닉네임과 친구 코드
- 로컬 도감의 공개용 클라우드 업로드
- 다른 기기에서 클라우드 기록 합치기
- 친구 코드로 친구 요청
- 받은 요청 수락·거절
- 친구별 보유 피규어 수와 보유 종 수
- 나만 보유 / 친구만 보유 / 공통 보유 비교
- 친구에게 사진 공개 여부 설정

## 서버에 올라가는 정보

- 포켓몬 번호와 이름
- 폼 이름
- 피규어 이름
- 제조사, 시리즈, 상품 번호
- 상태와 구입일
- 공개용 압축 썸네일

다음 정보는 서버에 올리지 않습니다.

- 구매 가격
- 구입처
- 보관 위치
- 개인 메모
- 원본 또는 고화질 사진

## 1. Supabase 프로젝트 생성

1. Supabase에서 새 프로젝트를 만듭니다.
2. 프로젝트가 준비되면 왼쪽 메뉴의 `SQL Editor`로 이동합니다.
3. 이 폴더의 `supabase-schema.sql` 전체 내용을 붙여넣고 실행합니다.
4. 오류 없이 완료됐는지 확인합니다.

## 2. 프로젝트 주소와 키 입력

Supabase Dashboard의 `Project Settings → Data API` 또는 API 설정 화면에서 다음 값을 확인합니다.

- Project URL
- Publishable key 또는 anon public key

`supabase-config.js`를 열고 입력합니다.

```js
window.SUPABASE_CONFIG = {
  url: "https://프로젝트ID.supabase.co",
  anonKey: "여기에_공개용_키"
};
```

`service_role` 키는 절대 입력하거나 GitHub에 올리지 마세요. 브라우저 앱에는 공개용 publishable/anon 키만 사용합니다.

## 3. 이메일 로그인 설정

Supabase Dashboard에서 `Authentication → Providers → Email`을 확인합니다.

- 테스트를 빠르게 하려면 이메일 확인을 잠시 끌 수 있습니다.
- 이메일 확인을 켜면 회원가입 뒤 인증 메일을 눌러야 로그인됩니다.
- 실제 친구와 사용할 때는 이메일 확인을 켜는 편이 좋습니다.

`Authentication → URL Configuration`에서 다음을 설정합니다.

- Site URL: GitHub Pages 사이트 주소
- Redirect URLs: 같은 GitHub Pages 주소와 끝에 `/**`를 붙인 주소

예시:

```text
https://사용자명.github.io/저장소명/
https://사용자명.github.io/저장소명/**
```

## 4. GitHub Pages 배포

1. 기존 저장소 파일을 v5 폴더의 파일로 교체합니다.
2. `supabase-config.js`에 자신의 값을 입력했는지 확인합니다.
3. GitHub Pages 배포가 완료될 때까지 기다립니다.
4. 사이트를 완전히 종료한 뒤 다시 엽니다.
5. 설정 메뉴에서 `온라인·친구 기능`을 누릅니다.

같은 GitHub Pages 주소를 유지하면 기존 IndexedDB 사진과 기록은 그대로 남습니다.

## 5. 첫 사용 순서

1. 계정 A와 계정 B를 각각 만듭니다.
2. 각 계정에서 `내 도감 업로드`를 누릅니다.
3. 계정 A의 친구 코드를 계정 B에서 입력합니다.
4. 계정 A에서 친구 요청을 수락합니다.
5. 두 계정 모두 최신 도감을 다시 업로드합니다.
6. 친구 목록의 `비교` 버튼을 누릅니다.

## 동기화 방식

현재 베타는 사용자가 `내 도감 업로드` 버튼을 눌렀을 때 서버와 맞춥니다.

- 로컬에 있는 기록은 서버에 추가 또는 갱신됩니다.
- 로컬에서 삭제된 기록은 다음 업로드 때 서버에서도 삭제됩니다.
- `클라우드 기록 받기`는 현재 기기에 없는 기록만 합칩니다.
- 같은 ID의 로컬 기록은 덮어쓰지 않습니다.

## 보안 구조

`supabase-schema.sql`은 Row Level Security를 활성화합니다.

- 자신의 기록만 작성·수정·삭제 가능
- 수락된 친구만 공개 기록 읽기 가능
- 친구 관계 당사자만 요청 열람 가능
- 썸네일은 소유자 또는 사진 공개를 허용한 친구만 접근 가능

SQL 실행 후 Supabase의 `Security Advisor`도 확인하는 것이 좋습니다.

## 무료 용량 절약

- 서버에는 360px 썸네일만 업로드합니다.
- 사진 한 장은 일반적으로 수십 KB 수준입니다.
- 원본과 1,440px 편집 사진은 기존처럼 기기에 남습니다.
- 사진 공개를 끄면 다음 업로드부터 새 썸네일을 올리지 않습니다. 이미 올라간 파일 제거 기능은 후속 버전에 추가할 수 있습니다.

## 문제 해결

### 온라인 메뉴에 Supabase 설정 필요 표시

`supabase-config.js`의 URL과 키가 기본값으로 남아 있습니다.

### `new row violates row-level security policy`

`supabase-schema.sql`을 전체 실행했는지 확인하고 Storage와 테이블 정책이 생성됐는지 확인합니다.

### 친구 비교 결과가 비어 있음

두 사용자가 친구 요청을 수락했는지, 각자 `내 도감 업로드`를 눌렀는지 확인합니다.

### 업데이트했는데 이전 화면이 나옴

홈 화면 앱과 Safari 탭을 모두 종료한 뒤 다시 열고 새로고침합니다. 서비스 워커 캐시는 v5 이름으로 변경되어 있습니다.
